# log4j2.xml 해석본

## 역할

로그를 어디에(콘솔/파일), 어떤 레벨부터, 어떤 형식으로 남길지 정의하는 설정 파일입니다.
Legacy `BookRentalPjt`의 `log4j.xml`(Log4j 1.x)과 이름은 비슷하지만, 이 파일은
후속 버전인 **Log4j2** 문법으로 작성되어 있습니다.

```xml
<configuration status="WARN">
    <Properties>
        <Property name="LOG_PATTERN">%d{yyyy-MM-dd HH:mm:ss} %-5p [%c{3}] - %m%n</Property>
        <Property name="LOG_PATH">logs</Property>
    </Properties>
    ...
</configuration>
```

`LOG_PATTERN`, `LOG_PATH`를 변수로 선언해 아래 `Appender`들이 반복해서 참조합니다.

## Appender: "어디에 기록할 것인가"

```xml
<Console name="Console" target="SYSTEM_OUT">...</Console>
<File name="FileForRootByInfo" fileName="${LOG_PATH}/spring-root-info.log">
    <ThresholdFilter level="INFO" onMatch="ACCEPT" onMismatch="DENY" />
</File>
<File name="FileForAppByDebug" fileName="${LOG_PATH}/spring-app-debug.log">
    <LevelRangeFilter minLevel="DEBUG" maxLevel="DEBUG" onMatch="ACCEPT" onMismatch="DENY"/>
</File>
<!-- INFO / WARN / ERROR 파일도 동일한 패턴으로 각각 정의 -->
```

`ThresholdFilter`는 "이 레벨 이상만 통과"이고, `LevelRangeFilter`는
"딱 이 레벨만 통과"입니다. 그래서 `spring-app-debug.log`에는 DEBUG 로그만,
`spring-app-info.log`에는 INFO 로그만 정확히 분리되어 쌓입니다.

## Logger: "누구의 로그를 어느 Appender로 보낼 것인가"

```xml
<Loggers>
    <Root level="info">
        <AppenderRef ref="Console" />
        <AppenderRef ref="FileForRootByInfo" />
    </Root>

    <Logger name="com.office" level="debug" additivity="false">
        <AppenderRef ref="Console"/>
        <AppenderRef ref="FileForAppByDebug"/>
        <AppenderRef ref="FileForAppByInfo"/>
        <AppenderRef ref="FileForAppByWarn"/>
        <AppenderRef ref="FileForAppByError"/>
    </Logger>
</Loggers>
```

```text
com.office 패키지 이하의 로그 (이 프로젝트의 모든 코드)
  -> level="debug" 이므로 DEBUG 이상 전부 캡처
  -> 레벨별로 4개 파일(debug/info/warn/error)에 각각 나뉘어 기록 + 콘솔 출력

com.office가 아닌 다른 패키지(Spring 프레임워크 내부 로그 등)
  -> Root 로거가 담당, INFO 이상만 콘솔 + spring-root-info.log에 기록
```

`additivity="false"`는 `com.office` 로거의 로그가 `Root` 로거로 다시 전달되어
중복 기록되는 것을 막습니다. 이 옵션이 없으면 `com.office`의 로그가
`FileForRootByInfo`에도 중복으로 쌓입니다.

## [HomeController.java](05_HomeController.java-해석본.md)와의 연결

```java
log.debug("DEBUG:: home()");
log.info("INFO:: home()");
log.warn("WARN:: home()");
log.error("ERROR:: home()");
```

이 네 줄이 각각 `spring-app-debug.log`, `spring-app-info.log`,
`spring-app-warn.log`, `spring-app-error.log` 네 파일에 정확히 한 줄씩 나뉘어
기록되는 것을 확인하기 위해 의도적으로 4단계를 모두 호출한 것으로 보입니다.

## 현재 코드에서 확인되는 주의점

`FileForAppByInfo`가 주석 처리된 버전(28~34행)과 활성화된 버전(45~50행) **두 번**
정의되어 있습니다. 활성화된 것은 `LevelRangeFilter`(INFO만), 주석 처리된 것은
`ThresholdFilter`(INFO 이상 전부)로 서로 다른 필터 방식입니다. 필터 정책을
바꿔보며 실험한 흔적이며, 현재는 `LevelRangeFilter` 버전이 사용 중입니다.
